# 🧪 Use Cases

## Current use cases

| ID | Actor | Use case | Preconditions | Expected result |
|---|---|---|---|---|
| UC-01 | Visitor | View landing page | Application available | Prototype landing page renders |
| UC-02 | Visitor | Open editor | Landing page or direct URL | Editor route renders |
| UC-03 | Visitor | Change sample code | Editor loaded | Text changes in local UI |
| UC-04 | Visitor | Change language label | Editor loaded | Selector displays chosen label |
| UC-05 | Visitor | Toggle theme | Editor loaded | Local styling changes |
| UC-06 | Visitor | Open chat panel | Editor loaded | Chat panel becomes visible |
| UC-07 | Visitor | Send team message | Team tab selected | Message appears locally |
| UC-08 | Visitor | Use AI preview | AI Preview tab selected | Fixed demo response appears |

## Negative use cases

| ID | Attempt | Expected current behavior |
|---|---|---|
| NEG-01 | Expect another browser to receive editor changes | No remote sync occurs |
| NEG-02 | Expect a new message to persist after reload | Local state resets |
| NEG-03 | Expect AI answer to be generated by a model | Fixed text is returned |
| NEG-04 | Expect sample avatars to authenticate users | They are decorative sample profiles |
| NEG-05 | Expect a private room or access control | No private-room service exists |

## Future security-sensitive use cases

Future requirements should include unauthorized room join, expired invitation, cross-room document access, disconnected member, duplicate message, malformed event payload, rate limit, account removal, and data deletion. Define expected denial and audit behavior before implementation.

## Use-case template guidance

Use unique IDs and state the actor, goal, preconditions, trigger, main flow, alternatives, errors, data changes, permission requirements, and test evidence. Do not create API or database use cases for services that do not exist.
