# 🧬 Dependency Security and Remediation

## Current verified state

The committed manifest pins Next.js to 15.3.1. A GitHub Actions npm audit on 17 November 2026 reported eight advisories: one critical, six high, and one moderate.

The audit summary listed these affected packages:

| Package | Severity | Dependency type |
|---|---|---|
| next | Critical | Direct |
| nanoid | High | Transitive |
| postcss | High | Transitive |
| sharp | High | Transitive |
| socket.io-parser | High | Transitive |
| source-map-js | High | Transitive |
| ws | High | Transitive |
| engine.io-client | Moderate | Transitive |

The npm audit report identified `next@15.5.29` as the available fix hint for the Next.js dependency and related framework dependency advisories. That version is a remediation candidate, not a completed update. The manifest and lockfile still contain the older dependency graph.

## Why this is a blocker

The Singapore Cyber Security Agency's 20 October 2026 advisory states that Next.js 10.x through 15.x versions before 15.5.28 are affected by two critical vulnerabilities, including remote code execution paths under specified deployment/features. The current 15.3.1 pin is below that fixed threshold.

The upstream Next.js security advisory GHSA-pc58-hwjq-p385 published 3 November 2026 lists 15.5.29 as a patched 15.x version. The official Next.js support policy states that Next.js 15 security releases are extended through 31 January 2027.

References:
- [Singapore CSA: Critical Vulnerabilities in Next.js, 20 October 2026](https://www.csa.gov.sg/alerts-and-advisories/alerts/al-2026-148/)
- [Next.js GHSA-pc58-hwjq-p385, patched versions](https://github.com/vercel/next.js/security/advisories/GHSA-pc58-hwjq-p385)
- [Next.js official support policy](https://nextjs.org/support-policy)

## Required remediation sequence

1. Create a dedicated dependency-upgrade branch.
2. Review Next.js 15.5 migration notes and update the direct dependency with npm, targeting the npm-reported patched version `15.5.29` on the 15.x maintenance line.
3. Run `npm audit fix` without `--force` to apply compatible transitive patches.
4. Inspect every changed dependency, especially React peer dependencies, PostCSS, Sharp, Socket.IO packages, nanoid, source-map-js, and ws.
5. Verify package.json and package-lock.json were both generated by npm and are consistent. Do not hand-edit integrity hashes or transitive dependency entries.
6. Run `npm ci`, `npm test`, `npm run typecheck`, `npm run docs:tree:check`, `npm run validate`, and `npm run build`.
7. Run `npm audit --json` again and review all remaining advisory details. Do not treat a changed count as a resolution without checking package paths and patched versions.
8. Review the actual production runtime and any feature-specific exploit preconditions.
9. Merge only after review and passing CI.

If a non-breaking audit fix cannot resolve an advisory, document the package path, affected code path, severity, owner, deadline, and approved mitigation. Do not suppress the finding or use a force upgrade merely to make the report green.

## Other vulnerable packages

The audit summary did not expose an npm automatic fix hint for engine.io-client, nanoid, socket.io-parser, source-map-js, or ws. Inspect the full npm advisory detail and dependency path before applying overrides or removing packages. Socket.IO packages are likely associated with the inactive experiment, but do not remove the client while pagebackup.tsx still imports it and TypeScript includes that file.

## CI behavior

The current quality workflow reports the audit summary but does not fail the general build based on the advisory count. This keeps compilation and repository validation observable while the security backlog remains explicit. **A green quality workflow is not a security clearance.**

## Framework lifecycle

Next.js 15 remains in Maintenance LTS with security releases extended through 31 January 2027. Plan and test a migration to Next.js 16 before that date, rather than treating 15.5.29 as a long-term endpoint.

## Closure criteria

This issue may be marked resolved only when:
- the patched framework and transitive package versions are committed;
- npm ci reproduces the committed lockfile;
- no critical/high npm audit advisory remains without an explicit reviewed exception;
- CI, type check, tests, and production build pass;
- release notes and dependency documentation reflect the actual upgraded versions.
